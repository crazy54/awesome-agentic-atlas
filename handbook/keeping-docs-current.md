# Keeping these docs current

Documentation here drifts the same way code does: someone changes the code and nobody changes the
sentence. This page lists which document to update when you change which code. Update it in the same PR.

## Which doc, for which change

| When you change… | Update |
|---|---|
| `SOURCES` in `scripts/10_parse_sources.py` (add or remove a list) | Root `README.md`: the list-of-lists table and every count derived from it. [overview.md](overview.md) if the headline number is quoted |
| `scripts/taxonomy.py` (topics or targets) | Root `README.md` topic and target tables; [frontend.md](frontend.md) facet page counts |
| Any numbered stage: new, removed, renumbered, or with new reads/writes | [pipeline.md](pipeline.md) (the table and the order), [ci-cd.md](ci-cd.md) (step lists), the stage's own docstring |
| `.github/workflows/*.yml` | [ci-cd.md](ci-cd.md). If a step moves, also the "Order matters" block in [pipeline.md](pipeline.md) |
| `docs/data.json`'s shape (`cols`, top-level keys, `schema_version`) | Root `README.md` "The data as an API". `tests/probe.mjs` checks those two tables against the data, so it goes red if you forget |
| `tests/run.mjs` `HARNESSES` (a harness added, removed or re-floored) | [testing.md](testing.md) table, `tests/README.md` table |

## Rules for numbers

1. **Re-measure; never copy.** A number in older prose is a claim about an older tree. This repository has
   been misled by counts copied forward ("nineteen harnesses" long after there were 26; "1,294 detail
   pages" at 8,858). A stale figure is worse than none, because it becomes the baseline the next check is
   compared against.
2. **Date every count.** Write "26 harnesses on 2026-09-25", not "26 harnesses".
3. **Give the command** when the measurement is not obvious, as [overview.md](overview.md) does for the
   list count.
4. **Prefer no number to a volatile one.** Where prose only needs the shape ("thousands of projects",
   "every list"), leave the figure out. Figures in the root README that readers do need are snapshot
   values; say which snapshot they come from.
5. **Measure the thing the claim is about.** Before you write a number down, check that you counted the
   right thing:
   - The committed `docs/data.json` and the post-ingest projection are different datasets.
   - `data.json` rows and `mega-list` entries are different counts.
   - The mega-list and `data.json` disagree slightly about how many lists a repo is on.
6. **Don't document a hazard as an invitation.** Write "this slot is contended; ask first", not "slot 11 is
   free".

## What is generated, and so must never be hand-edited here

`docs/` (with the few hand-written exceptions listed in [contributing.md](contributing.md#generated-vs-hand-written))
and `mega-list/` are regenerated by CI. Documentation belongs in `handbook/`, `tests/README.md`,
`config/README.md`, the root `README.md` and the scripts' docstrings, never in `docs/`, which is published as the website.
